# Reglas de Trabajo — Nuestro Universo

Estas reglas garantizan que el proyecto se construya con calidad, orden y respeto por lo aprobado. **Cualquier sesión de desarrollo debe respetarlas.**

---

## Las 7 reglas

### 1. Una fase a la vez
Solo se trabaja en UNA fase. Al terminarla, se **detiene por completo** el trabajo y se espera una de estas respuestas para continuar: *Continuar*, *Siguiente fase*, *Aprobado*, *Sigue* o *Adelante*.

### 2. Preguntar al terminar cada fase
Al final de cada fase se pregunta al propietario:

- ¿Te gusta cómo quedó?
- ¿Quieres cambiar algo?
- ¿Quieres mover algo?
- ¿Quieres cambiar colores?
- ¿Quieres agregar algo?
- ¿Quieres eliminar algo?

Se espera la respuesta antes de continuar.

### 3. Nunca modificar lo aprobado
Si una función nueva requiere modificar una parte ya aprobada, se pide autorización explícita antes:

> "Para implementar esta función necesito modificar la sección X. ¿Me autorizas hacerlo?"

### 4. No destruir código existente
Se reutilizan componentes. No se duplica código. Todo permanece modular.

### 5. Revisión automática al terminar cada fase
Verificar antes de mostrar el resultado:

- errores
- responsive (PC, tablet, iPhone, Android)
- rendimiento
- accesibilidad
- organización
- código innecesario

### 6. Mejores ideas: proponer, no implementar
Si se detecta una mejor idea, se **explica** (ventajas, desventajas, por qué sería mejor) y se espera la decisión del propietario.

### 7. Pensar en el futuro
Todo debe construirse para crecer durante años. Sin soluciones temporales.

---

## Reglas adicionales del proyecto

- **Errores:** ante cualquier error, detenerse, corregirlo y continuar. Nunca ignorar errores.
- **Código repetido:** refactorizar siempre.
- **Mantenibilidad:** nombres claros, archivos ordenados, funciones pequeñas, componentes reutilizables.
- **Compatibilidad:** PC, tablet, iPhone y Android.
- **Documentación:** cada módulo comentado (qué hace, cómo funciona, dónde modificarlo, qué archivos usa).

## Resumen de entrega de cada fase

Al finalizar una fase se entrega:

- ✅ Qué se hizo
- 📁 Qué archivos se modificaron
- 🆕 Qué componentes nuevos existen
- ⚙️ Qué falta por desarrollar
- 💡 Posibles mejoras (sin implementarlas)
